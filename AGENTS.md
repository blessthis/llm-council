# AGENTS.md — blessthis-llm-council

> Source of truth for how agents are authored, transformed, and shipped across the 6 supported consumer hosts. Read this before touching anything in `agents/` or `docs/agent-templates/`.

## TL;DR — the canonical workflow

```
┌─────────────────────────────────────────────────────────────────┐
│  agents/pi/blessthis-council-<role>.md   ← EDIT THESE (canonical)│
│  (pi format: lowercase tools, mcp__llm-council__*)               │
└──────────────────────┬──────────────────────────────────────────┘
                       │ pi extension hook (tool_result on edit/write)
                       │ sends main agent a nudge via sendUserMessage
                       ▼
┌─────────────────────────────────────────────────────────────────┐
│  Main agent spawns 5 parallel subagents                         │
│  Each subagent task: "Run /regen-for-host <host>"                │
└──────────────────────┬──────────────────────────────────────────┘
                       │ /regen-for-host.md prompt-template expands
                       │ with $1=<host>, loads per-host transformation rule
                       ▼
┌─────────────────────────────────────────────────────────────────┐
│  agents/<host>/blessthis-council-<role>.{md,toml,agent.md}      │
│  ← GENERATED, never hand-edit                                   │
└─────────────────────────────────────────────────────────────────┘
```

**You only ever edit `agents/pi/*.md` files.** Everything else is generated by subagents you spawn after the hook nudges you. The installer copies the generated files into each host's agent directory at install time.

## Directory layout

```
agents/
├── pi/          ← CANONICAL (human-edited). Format reference: docs/agent-templates/pi.md
├── claude/      ← GENERATED
├── codex/       ← GENERATED (TOML)
├── cursor/      ← GENERATED
├── copilot/     ← GENERATED (+ parent orchestrator)
└── gemini/      ← GENERATED
```

The directory name IS the host. Filenames inside are identical stems (`blessthis-council-<role>`), with host-specific extension (`.md` default, `.toml` for codex, `.agent.md` for copilot).

## Two kinds of files — do not mix them

| Kind | Where | Contents | Editable? |
|------|-------|----------|-----------|
| **Agent content (canonical)** | `agents/pi/blessthis-council-<role>.md` | The agent's `name`, `description`, `tools:` (pi style), and the markdown body (instructions/persona). Real content, real tool lists, real prose. | ✅ by humans |
| **Agent content (derived)** | `agents/<host>/blessthis-council-<role>.{md,toml,agent.md}` | Same content, rewritten into the host's format by a subagent running `/regen-for-host <host>`. | ❌ generated |
| **Host format template** | `docs/agent-templates/<host>.md` | The host's pure format spec: file paths, frontmatter schema, tool-name conventions, `model:` rules, gotchas. **Generic placeholder example (`my-agent`), NEVER our real agent content.** | ✅ when the host's format changes |
| **Transformation matrix** | `docs/agent-templates/INDEX.md` | How pi frontmatter keys map to each host's keys (the rules the subagent follows). | ✅ when a host's mapping changes |
| **Regen hook (pi extension)** | `.pi/extensions/regen-agents/index.ts` | Listens to `tool_result` on edits to `agents/pi/*.md`; nudges main agent via `sendUserMessage`. Does NOT spawn subagents itself. | ✅ if hook behavior needs changing |
| **Regen prompt-template** | `.pi/prompts/regen-for-host.md` | Slash-command `/regen-for-host <host>` — expands into the per-host transformation rule that a regen subagent executes. | ✅ if transformation rules change |

The mistake to avoid: putting `blessthis-council-architect`'s real description/tools/body into `docs/agent-templates/cursor.md`. The template file must stay a generic reference so it documents the *format*, not a specific agent.

## Canonical pi format (the source)

A canonical agent file `agents/pi/blessthis-council-<role>.md` looks like:

```markdown
---
name: blessthis-council-architect
description: >-
  <real description here>
tools: read, write, edit, grep, find, ls, bash, mcp__llm-council__council_start, mcp__llm-council__council_poll, mcp__llm-council__council_answer, mcp__llm-council__council_ask, mcp__llm-council__council_score, mcp__llm-council__council_reveal, mcp__llm-council__council_close
# model omitted → inherits session model
---

<real agent body / system instructions here>
```

Rules:
- **Filename:** `blessthis-council-<role>.md` inside `agents/pi/`. The `blessthis-council-` prefix is mandatory (uninstall-safety; bare `council-*` would clobber unrelated agents). The `<role>` is the agent's role (architect, bug, review, conductor, …). No host suffix — the directory (`pi/`) is the host.
- **`name:`** MUST equal the filename stem: `blessthis-council-<role>`.
- **`tools:`** lowercase, comma-separated. pi built-ins: `read, write, edit, grep, find, ls, bash`. MCP tools: `mcp__<server>__<tool>` double-underscore. Our server is always registered as `llm-council`, so tool refs are `mcp__llm-council__council_*`.
- **`model:`** OMITTED. pi does not accept the `model: inherit` keyword (Claude does). Blank = inherit.
- **Body:** markdown, host-agnostic prose. No host-specific formatting in the body — the regen subagent copies it verbatim to every derived file.

## The regen pipeline (hook → main agent → subagents)

This is a DEV-process mechanism, not part of the shipped installer. It keeps `agents/<host>/` in sync when `agents/pi/` changes during development of this repo.

1. **Hook fires.** `.pi/extensions/regen-agents/index.ts` listens to pi's `tool_result` event. When the main agent finishes an `edit`/`write` on `agents/pi/blessthis-council-*.md`, the hook debounces (300ms) and calls `pi.sendUserMessage(nudge)` with a message telling the main agent to regenerate.
2. **Main agent spawns subagents.** On receiving the nudge, the main agent spawns 5 subagents in parallel (one per non-pi host: claude, codex, cursor, copilot, gemini). Each subagent's task is literally: `Run /regen-for-host <host>` (with the host name substituted).
3. **Subagent expands the prompt-template.** Each subagent is a headless pi instance. It receives the task, the slash-command `/regen-for-host <host>` expands `.pi/prompts/regen-for-host.md` with `$1 = <host>`, which loads the full per-host transformation rule.
4. **Subagent does the transformation.** For each `agents/pi/blessthis-council-<role>.md`: parse YAML frontmatter → rewrite per `docs/agent-templates/<host>.md` + the matrix in `INDEX.md` → write `agents/<host>/blessthis-council-<role>.{md,toml,agent.md}` with a `GENERATED` marker header.
5. **Copilot special case:** the subagent also maintains `agents/copilot/blessthis-council-conductor.agent.md` (parent orchestrator with `tools: [agent]` + `agents: [blessthis-council-architect, ...]` whitelist).

The subagent (LLM) does the transformation — not a sed script — because Cursor drops `tools:` entirely, Copilot needs a parent orchestrator, and Codex is TOML. The hook is event glue only.

## When to edit what

- **Adding a new agent role** (e.g. `blessthis-council-security`) → create `agents/pi/blessthis-council-security.md`, save. The hook nudges you; spawn the 5 regen subagents.
- **Changing an agent's description/tools/body** → edit `agents/pi/blessthis-council-<role>.md`, save. Hook nudges; spawn regen subagents.
- **A host changed its format** (e.g. Cursor adds a `tools:` key in a new version) → update `docs/agent-templates/cursor.md` + the INDEX.md mapping; then trigger a full regen by re-saving any `agents/pi/*.md` (or manually spawn 5 subagents with `/regen-for-host <host>`).
- **Adding a new host** → add `docs/agent-templates/<newhost>.md` (pure format reference), add a row to INDEX.md, add the host to `TARGET_HOSTS` in `.pi/extensions/regen-agents/index.ts`, extend the matrix in `.pi/prompts/regen-for-host.md`. Then regen.
- **Changing the transformation rule for a host** → edit `.pi/prompts/regen-for-host.md` (the rule the subagent follows) and/or `docs/agent-templates/INDEX.md` (the matrix). Then regen.

## Naming — what stays constant vs what transforms

| Thing | Value | Constant? |
|-------|-------|-----------|
| MCP server registration name | `llm-council` | ✅ constant everywhere |
| MCP tool names (server-exposed) | `council_start`, `council_poll`, … | ✅ constant everywhere |
| Agent filename prefix | `blessthis-council-` | ✅ constant everywhere |
| Agent `name:` field | `blessthis-council-<role>` | ✅ constant everywhere |
| Agent file location | `agents/<host>/blessthis-council-<role>.{md,toml,agent.md}` (dir = host) | ❌ per host |
| MCP tool reference syntax in `tools:` | `mcp__llm-council__council_*` (pi/claude) / `mcp_llm-council_council_*` (gemini) / `llm-council/council_*` (copilot) / global (cursor/codex) | ❌ per host |
| Built-in tool names | `read` (pi) / `Read` (claude) / `read_file` (gemini) / … | ❌ per host |
| `model:` handling | omit (pi) / `inherit` (claude) / drop (others) | ❌ per host |
